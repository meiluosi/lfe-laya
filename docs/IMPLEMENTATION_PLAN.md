# 实施与验收计划

状态：M0 已完成；2026-09-29 用户明确授权下一轮实验及 M1–M5，完整目标已建立。共享生态、观察室、模型记录、分支及独立学习均已进入实现与验证；下一轮多种子实验正在运行。执行切片与证据见 [本轮进度](EXECUTION.md)。M0 历史证据保持独立。

## 工作方式

通过可运行的纵向切片推进。每个任务先明确预期行为和验证方式，然后实现、验证、记录结果。计划中的任务粒度是建议，允许在不改变已批准范围的情况下调整拆分。

当前已授权推进下一轮算法实验及 M1–M5，不设成本预算。以 P0 修订方向为依据继续实现，真实浏览器验收仍逐项执行，不把授权等同于功能验证。分切片持续工作，技术验证结果用于修订参数；学习收益与工程完成分别报告。

M0–M4 交付基础生态与验证设施；M5 才交付首个包含路线 B 和 L1 的学习版本。延迟后果与有成本交流属于后续已纳入的目标，分别推进。学习定义、主备路线与实验规则以 [持续学习方案](LEARNING.md) 为准。

已完成首轮 [开源复用调研](OPEN_SOURCE.md)。P0/M0 优先验证现有渲染、图表、RL 基线和训练组件，避免重复实现通用设施；文档调研不等于兼容或性能验证通过。选型验证纳入现有阶段，不另起大规模框架工程。

默认先把可点击原型做成完整可审核产物，再集中走查；不要求每一张线框或每个样式选择都单独审批。是否复用原型代码取决于正式接口和可维护性，不强行沿用演示逻辑。

## M0：真实模型与最小行为验证

目标：先确认真实 Laya 能参与有限决策，并验证独立小策略能够接收后果、更新参数和保存学习状态；该阶段不宣称持续学习已成功。

| 任务 | 产物 | 完成条件 |
| --- | --- | --- |
| 运行环境确认 | 设备、运行时、模型和许可证记录 | 明确实际使用的版本、后端和资源要求 |
| 决策协议 | 请求、响应与错误语义 | 能区分提案、执行结果和 provider |
| 情境验证 | 小型可重复运行的情境集 | 真实输出可检查，调参与验收样例分离 |
| 批量测试 | 原始测量与摘要 | 报告不同批量的吞吐、耗时、内存与失败情况 |
| 最小动作循环 | 单个体感知、决策、执行记录 | 一次真实 Laya 响应能够改变模拟动作 |
| 小策略可行性 | 最小反馈任务、候选融合与独立学习实例 | 真实 Laya 偏好可被小策略使用，反馈能驱动有记录的更新，两个个体不共享可变学习状态 |
| 训练与评估规格 | 算法、网络预算、奖励公式、任务时长及预定评估标准 | 测量单个体与小批量联合开销；评估标准在留出测试前固定 |
| 开源 RL 适配验证 | Gymnasium/SB3 最小基线与 TorchRL 等训练组件比较（V2/V3） | 实际检查候选屏蔽、个体隔离、恢复与依赖兼容；只选必要的一套正式训练方案 |
| 世界与训练桥接 | TS 无界面核心与 Python 本地协议小验证（V4） | 测量吞吐与状态一致性；若考虑 Python 世界，先给出收益和架构调整方案 |

最小动作循环只需验证单个体的能量与动作变化，不依赖完整 M1 世界，避免阶段循环依赖。

小策略验证使用独立的简化资源选择任务；确定性接口测试可用合成样本，但模型集成证据必须包含真实 Laya。该阶段给出哪些测试仅验证数据管道、哪些测试评估行为改善，不将简化任务成功外推为生态成功。

验收：必须实际调用模型，保存完整证据。不能以 mock、静态记录或只启动服务代替。最终确定初始规模、决策频率、默认 checkpoint 和小策略训练预算。分别记录固定 Laya 和路线 B 的资源需求，不假定 48 个体训练必然实时。

若模型对数值状态或有限动作理解不可靠，先简化候选和输入，并报告改进前后结果。若仍不适合，提出带证据的替代方案，不静默把全部实现改成规则大脑。

采用 PettingZoo 时先以有限身份/无繁殖环境验证 Parallel API，再定义长期出生死亡映射。不能把向量化共享策略训练当作每个个体独立学习。CleanRL 和 Avalanche RL 本轮仅为参考候选，不原样并入主环境的依赖。

## M1：可持续运行的生态核心

依赖：P0 核心流程走查完成，M0 的决策协议与最小学习闭环稳定。

实现环境场、连续位置、障碍、受控随机数、能量账本、摄食、运动、代谢、死亡、繁殖、性状变异与固定容量地点记忆。先使用规则大脑调试，同时保留真实 Laya 的相同动作接口。支持资源分布日程、独立随机流、关闭繁殖/变异的实验开关，以及带个体身份和时间区间的真实行动经历。

验收重点：

- 无重复 ID、负资源、无效坐标、穿墙或死亡个体继续行动。
- 资源竞争、繁殖和死亡回收不会创造能量，账本在容差内闭合。
- 后代拥有合法性状与正确父代关系，随机种子可复现规则运行。
- 一个繁殖决策只产生一次结算，动作拒绝后不会隐式改选或反复执行。
- 感知范围与障碍遮挡生效，模型输入没有全局信息泄露。
- 长时间加速运行不会无限积累个体、内存或事件。
- 至少有一个预设场景能观察到多代繁殖；允许其他种子灭绝，不以所有世界永久稳定作为验收。
- A/B/A 资源日程可复现且阶段真值不进入生命体观测；奖励反馈与全局评价指标分离，死亡和时间截断语义明确。

## M2：第一版可观察前端

依赖：P0 修订后的原型和样式约定，M1 可导出只读快照与事件。

依据 P0 原型实现生态画布、镜头、个体选择与跟随、能量和性状面板、资源图层、暂停/单步/倍速、营养与障碍工具。接入 Worker，保持界面与模型等待解耦；逐项用真实数据替换示例，并保留尚未接入功能的明确标识。

验收重点：

- 在实际浏览器中验证选择、缩放、拖动、暂停、单步及干预。
- 相同模拟时长在不同渲染帧率下不会改变规则运行结果。
- 世界状态、个体面板和曲线保持一致，不显示虚构数据。
- 显示规则、真实 Laya、回放、降级和等待状态。
- 检查桌面与窄屏布局、中文可读性、颜色之外的标识与减少动态效果。
- 在目标机器记录帧耗时和模拟速度；发现瓶颈再优化，不先引入复杂 GPU 计算架构。

## M3：完整 Laya 运行与记录回放

依赖：M0、M1、M2。

接通多生命体批量推理、同步决策屏障、请求失效处理、严格实验暂停与显式降级。加入保存、导出、动作记录、从快照重放、基础谱系展示和数据驱动事件时间线。

V5 在此阶段验证 Dexie 的本地世界存储与导出格式；M5 再验证它与 Python 学习检查点组成的完整恢复包。TensorBoard 可用于研发观测，不能替代产品事件日志或训练快照。

验收重点：

- 存在可检查的真实 Laya 多个体运行记录，并可定位输入、返回动作和执行结果。
- 重置或切换世界后旧响应不会污染新世界。
- 同一步取消并重试时，旧尝试迟到不被接受；每个逻辑决策最多提交一次。
- 部分成功不提前推进世界，单纯暂停不丢弃有效结果，等待期间的环境修改会使整轮观测失效。
- 暂停、超时、无效响应与服务中断都有一致且可见的处理。
- 固定版本下，记录回放在指定检查点产生相同世界状态哈希。
- 记录达到容量阈值时按设计处理，不静默声称完整保存。
- 规则、Laya 和降级决策在指标中可分开统计。
- 请求的模拟时间与真实耗时单位不混用，输入过长、空候选或无效数值显式失败；回放不计为新模型调用。

## M4：实验分支与基础生态交付

依赖：M3。

实现从同一快照创建实验分支，支持选择不同大脑或改变一个环境参数。提供配置、指标和结果导出，以及运行、停止和故障处理文档。

建议首轮比较 10 个种子，在固定模拟时长下分别运行规则与 Laya；实际数量根据 M0 成本确定并如实披露。比较种群、繁殖成功、谱系延续、动作分布、资源利用和计算成本。

验收不是“Laya 必须胜出”。需要诚实展示改善、无差异或退化，区分模型失败与环境规则导致的结果。单个有趣案例可作为展示，不作为普遍结论。

基础生态交付包含可运行应用、真实模型接入说明、规则离线模式、回放样例、功能验证记录、性能测量和已知限制。此时只完成学习所需的基础设施，不能标为持续学习目标已完成。

## M5：路线 B 与首个学习版本

依赖：M0 小策略验证、M1 环境经历及 M3/M4 记录与实验设施。

| 任务 | 产物 | 完成条件 |
| --- | --- | --- |
| 个体学习运行时 | 独立参数、优化器、经验和更新协议 | 实际更新小策略，Laya 权重保持固定；参数/记忆无跨个体泄露 |
| 行动反馈闭环 | 有持续时间的轨迹与版本化奖励 | 拒绝、死亡、截断及降级数据按协议处理，不重复奖励 |
| L1 资源变化 | A/B/A 场景与同一个体轨迹 | 切换不重置学习状态，隐藏环境日程不进入模型输入 |
| 学习状态保存 | 完整训练快照与分支 | 参数、优化器、经验、随机状态可恢复；分支无共享可变引用 |
| 成长前端 | P0 中的成长体验接入真实经历、策略版本和冻结比较 | 移除对应示例逻辑，区分已更新与已验证改善，显示失败和死亡 |
| 学习对照 | 规则、固定 Laya、简化 A、B、无 Laya 小网络及冻结 B | 多种子、留出环境、预定指标，分别检验学习和 Laya 的贡献 |

工程验收包括：重复训练请求只提交一次、迟到更新不能覆盖新策略、部分训练失败不推进世界、暂停世界不继续学习、冻结评估不修改学习参数、后代默认全新初始化、终止反馈正确结算。

学习验收包括：先在关闭繁殖和变异的 L1 场景中追踪同一初始队列，完整记录死亡与失败；再恢复生态繁殖观察两种机制共同作用。评估适应时间、累计损失、旧能力保留、能量与生存结果；使用 M0 预先确定的标准，不以训练奖励上涨代替留出效果。

展示回放不重新训练；继续学习必须基于完整快照。锁定运行时验证恢复过程，跨设备只能报告实际验证过的容差，不承诺梯度逐位复现。

工程闭环成功与学习收益得到证据分别标记。若暂未观察到可靠收益，交付实验结果和限制，继续定位样本量、奖励或学习策略问题，不宣称学习目标已达成，也不静默切到 A/C。

M5 完成后才形成首个学习版本：能观察个体因为经历改变策略，并提供检查这种改变是否有效的对照与证据。

## 后续机制与备选路线

路线 B 跑通后按 L2 → L3 扩展。A/C 的完整原型安排在 B 之后；必要的简化 A 对照已在 M5 使用。机制都保留，但不同时引入，避免无法判断学习来源。

| 机制 | 研究问题 | 对照 |
| --- | --- | --- |
| L2 延迟后果食物 | 能否关联即时补能和之后的损伤？ | 匹配外观、关闭延迟损伤；保持反馈真实，不提前标注毒性 |
| L3 信号与分享 | 信息和资源转移能否帮助群体延续？ | 分别关闭信号／分享，并记入发送与转移成本 |
| 捕食与防御 | 是否形成持续的不同摄食策略？ | 无捕食环境，保持其他条件一致 |
| 环境压力 | 哪些性状在环境改变后更容易延续？ | 不施加变化或改变发生时刻 |
| 可演化网络结构 | 网络结构的跨代变化是否改善生存与学习？ | 固定网络结构，保持个体学习规则一致 |
| 路线 A 完整经验适应 | 不更新神经参数能否获得同样的适应？ | 与 B 使用相同观测与环境，报告记忆和统计容量 |
| 路线 C 持续微调 Laya | 更新预训练模型是否提供额外收益？ | B/C 在声明的交互及计算预算下训练后分别冻结评估，检查遗忘和知识共享范围 |
| 后天经验传承 | 学习经验如何影响后代和群体？ | 明确传递参数或记忆，关闭传承作为对照 |
