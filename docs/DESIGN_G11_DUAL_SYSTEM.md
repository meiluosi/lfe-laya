# 设计 G11：双系统架构——Laya（系统 1）+ LLM（系统 2）+ harness（记忆与观测）

状态：**已开工**（2026-10-28 用户确认：DeepSeek，模型名用 `deepseek-flash`，即官方文档当前推荐的 Flash 名，由 DeepSeek-V4.1-Flash-1017 提供服务；旧名 `deepseek-v4-flash` 已被官方改指向同一模型；key 由用户放进本地 `.env`；费用不设预算上限，代码里只保留防失控的调用数保护 `LLM_MAX_CALLS`，默认 200000）。S1（harness、桩模型、条件 T、记录回放、测试 7 项）已完成；探针脚本 `packages/evo/dual-probe.ts` 已写好，等 key。用户 2026-10-28 决定：LLM 用用户提供的 API key；目标是验证新的架构假设（双系统），可以做的研究因此更多。旧链路（结构化个体 + 进化先天 + 终身学习）保留为基线，预注册 20 照常完成。

## 1. 假设（架构层面）

旧链路里最弱的环节都是“需要推理”的：环境变了靠预测误差启发式发现（regime）；线索只能当标签（cue）；固定 Laya 读不出线索含义（G9 两次探针未过）。**假设 A**：让一个会推理的系统 2 在“意外”时介入，读自己的经历（和可见的线索句子），判断“环境是否变了、是不是见过的环境”，由 harness 去切换 / 新开信念表，可以在 A/B/A 世界里取得接近或超过 regime 的保留，并且在 regime 做不到的地方（读线索、解释变化）有额外收益。**可证伪**：若系统 2 的保留不优于“同样触发条件 + 规则化动作”的对照，则增益不来自推理。

## 2. 架构（谁拥有什么）

```
世界（模拟器：唯一的状态所有者）
  └─ 每个 tick：个体的局部观测（含可选的线索句子 season）
系统 1（每 tick，快）：结构化个体 = 固定 Laya 先验 + 个体信念表（预注册 17 的 plain 基因组，冻结，不再进化）
harness（个体私有）：
  ├─ 经历日志：最近 N 次“吃了什么描述 → 结果（以文字档位表述）”
  ├─ 记忆笔记：系统 2 写下的短句（上限 M 条，只含该个体自己的经历）
  ├─ 意外触发器：预测误差滑动平均超过阈值，带冷却
  └─ 动作执行器：把系统 2 的结构化建议变成对系统 1 的操作（新开表 / 切到第 i 张表 / 保持）
系统 2（只在触发时，慢）：LLM，输入 = 经历日志 + 笔记 + 当前表摘要 + （可选）线索句子；输出 = 严格 JSON（是否变了、假设一句话、建议、要写的笔记）
```

不变量：LLM 只提交“信念管理”的建议，不能改能量、位置或存活；个体输入只含自身状态、有限记忆与局部观测，**隐藏真值（食物真实影响、环境状态）不进入提示**；提示里的结果用个体自己感受到的档位（“恢复了能量 / 损失了能量”），不给环境阶段名；先天（基因组）/ 后天（信念表、笔记）/ Laya 感知 / **系统 2 推理**四个来源分别标注；Laya 权重不变，LLM 权重不变；每次调用的输入、输出、模型版本、耗时、费用记录在案，迟到或失败的响应按“无建议”处理，不阻塞世界。

## 3. 世界时间与系统 2 的耗时

第一版：**系统 2 的思考不占模拟时间**（世界在等待时暂停）——这是一个明确披露的简化，等价于“推理瞬间完成”。它高估了系统 2 的价值。后续变体：每次调用扣固定的模拟 tick 或能量（“思考有代价”），再比较。

## 5. 小探针（开发期，非确认性）

世界：K=6，A/B/A，无线索（再加线索版），开发方言池 `test`，开发期基因组（种子 201、202 的 plain），个体 8 个，立即反馈；每个条件 8 个世界。指标：节省（同预注册 18）、适应度、LLM 调用数与 token 数。先写的读法：

- 其他 → 不确定；S2x 若接近 S2，说明 LLM 没在读经历，停。

## 8. 风险与限制

- 世界时间不计思考成本（见 §3），第一版会偏乐观；LLM 输出有随机性与版本漂移，所以所有调用记录在案，评估靠记录回放而不是随机种子；
- 提示措辞是自由度很大的设计选择，探针只试一版，不据结果反复调提示再重跑（调提示须在开发期、记录并披露）；
- 若系统 2 只是在“检测到意外就新开一张表”，那它与 T 无差别——这正是条件 T 存在的原因；
- 线索句子由作者撰写，LLM 读得懂不代表理解了环境；它回答的是“能否用语言读线索”，不是“Laya 是否理解环境”。

## 9. 冒烟记录（2026-10-28，接入 DeepSeek 的第一次调用）

- 1 个世界、S2，思考模式缺省开启、max_tokens 400：55 次调用里 **17 次返回空内容**（推理 token 用完上限），19 次解析失败，仅 1 次动作被采纳。原因是官方缺省 `thinking: enabled`，推理 token 占用 max_tokens。
- 同一批 6 条提示（4 条“结果与表的预期不一致”）对比：**思考关闭**（max_tokens 300）1.5 秒、193 个输出 token，4 条不一致里 3 条判 new、1 条 keep；**思考开启**（max_tokens 4000）22.4 秒、6650 个输出 token，3 条判 new、1 条 keep。判断质量相近，思考关闭快约 15 倍、输出 token 少约 34 倍。
- **决定**：探针主条件用思考关闭（`LLM_THINKING=disabled`，缺省）；若有迹象，再加一个思考开启的变体重复。冒烟日志不进入探针（探针另开输出目录，缓存键含提示，不会混用）。
- 观察：意外触发器在稳定阶段也常触发（约每个体 7 次 / 世界），系统 2 大多回答 keep，对误报不敏感；条件 T 同样触发 68 次 / 世界。这是触发阈值 0.5 偏敏感，不改（探针不据结果调阈值）。

## 10. 小探针 v1 的结果（2026-10-28；`experiments/evo/g11-probe-01/`，调用日志 `llm-log.jsonl`，2916 次调用、约 205 万输入 / 10.5 万输出 token、平均 0.82 秒 / 次；开发期基因组 plain 201、202；A/B/A、K=6、开发池 test；每个条件 8 个世界；模型 `deepseek-flash` 思考关闭）

| 条件 | 节省（种子 201 / 202） | 适应度（201 / 202） | 每世界调用数 |
| --- | --- | --- | --- |
| P plain | −0.136 / −0.129 | .783 / .729 | — |
| R regime（基线） | +0.095 / +0.206 | .864 / .863 | — |
| T 触发 + 规则动作 | −0.050 / −0.049 | .639 / .694 | 66 / 70 次触发 |
| **S2 触发 + LLM** | **−0.157 / −0.171** | .752 / .737 | 72 / 72 |
| S2c + 可见线索 | −0.169 / −0.126 | .754 / .722 | 76 / 75 |
| S2x 负控制（结果错配） | −0.233 / −0.165 | .643 / .641 | 68 / 67 |

**按运行前写定的判据读数**：S2 − T = −0.107 / −0.123（判据要求 ≥ +0.05），S2 ≤ T + 0.02 → **无迹象**；S2 也不接近 R（落后约 0.25–0.38）。S2 的节省与不用系统 2 的 P 几乎相同。负控制 S2x 的适应度明显低于 S2（.64 对 .74–.75），说明 LLM 确实在读经历（错配会伤害它），但读了之后没有比 plain 做得更好。S2c 与 S2 无差别：可见线索没有带来可见的收益。

**决策分布**（所有调用）：S2 keep 719 / new 182 / switch 102；S2c 759 / 154 / 139；S2x 414 / 337 / 110。在提示里明确出现“结果与当前表预期相反”的 460 条 S2 调用里，LLM 仍有 219 条（48%）回答 keep。调用发生时已有 1 / 2 / 3 / 4 张表的比例为 560 / 238 / 117 / 88。

**诊断（harness 设计层面的疑点，未检验）**：触发器用绝对阈值 0.5，稳定阶段也每个体约触发 9 次 / 世界（上限 12 次 / 一生），可能在反转与回归发生前就把调用与冷却用掉，并让表空间被误报占满；T 也有同样问题，且 T 的适应度比 P 还低。所以 v1 的“无迹象”既可能是系统 2 本身无用，也可能是触发器太差。按设计 §8 的约束，v1 的结果照实记录，不改判据；允许在开发期做**一次披露的第二轮**，只改触发器（见 §11），提示与判据不变。

## 11. 第二轮（v2，开发期，运行前写定）

**只改触发器，提示、判据、世界、基因组、模型设置不变**：触发条件改为“当前表的误差滑动平均 > 0.35，且比该个体自己的慢基线（误差滑动平均的慢速平均，速率 0.02）高出 0.2”，即只在误差**上升**时触发；每个体一生的调用上限 12 → 20；冷却 100 tick 不变。T 使用同一触发器。判据同 §5：**有迹象** = S2 − T ≥ +0.05 且 S2 ≥ R − 0.05，两个种子方向一致；**无迹象** = S2 ≤ T + 0.02；S2x 接近 S2 说明 LLM 没在读经历。**不再有第三轮**：v2 的结果无论如何照实记录；若有迹象，才设计预注册 22（新种子、新世界、新提示冻结）；若无迹象，G11 的结论是“在这一版 harness 与提示下，系统 2 没有带来保留收益”。

## 12. 小探针 v2 的结果（2026-10-28；`experiments/evo/g11-probe-02/`，1216 次调用；触发器改为“误差上升”，其余同 v1）

| 条件 | 节省（种子 201 / 202） | 适应度（201 / 202） | 每世界触发数 |
| --- | --- | --- | --- |
| P plain | −0.136 / −0.129 | .783 / .729 | — |
| R regime | +0.095 / +0.206 | .864 / .863 | — |
| T 触发 + 规则动作 | −0.092 / +0.030 | .671 / .664 | 35 |
| S2 触发 + LLM | **−0.139 / −0.171** | .752 / .733 | 31 |
| S2c + 可见线索 | −0.122 / −0.140 | .810 / .762 | 32 / 31 |
| S2x 负控制 | −0.190 / −0.041 | .651 / .714 | 31 / 32 |

**按 §5 / §11 的判据**：S2 − T = −0.047 / −0.200（要求 ≥ +0.05）；S2 ≤ T + 0.02 → **无迹象**。触发数从约 70 降到约 31 / 世界，但节省没有改善。S2c 的适应度比 S2 高约 0.03–0.06（.810 / .762 对 .752 / .733），节省差别仍在噪声内；这是“可见线索略有帮助”的一个弱提示，未检验。S2x 在种子 202 上的节省（−0.04）反而好于 S2，说明这一轮的节省指标噪声很大（每个条件仅 8 个世界）。

**结论（v1 + v2，按 §11“不再有第三轮”）**：在这一版 harness 与提示下，LLM 系统 2 **没有**带来保留收益；它的节省与不用系统 2 的 plain 接近，明显低于 regime。可能原因（均未检验）：LLM 对带噪声的少量样本不敏感（对“结果与预期相反”的提示仍常回答保持）；单次结果噪声大，序贯概率推理不是 LLM 擅长的；新开的表是空表，切换后要重新学习。这与用户提出的“LLM 读到不准确的经历会被误导，应引入贝叶斯式的概率推理辅助”的判断一致，下一步设计见 §13。

## 13. 设计：贝叶斯引擎 + LLM 作带噪声传感器，以及第一步“线索读取探针”（2026-10-28，用户同意此分工）

**分工（用户提出“引入贝叶斯类理论辅助”，我提出的落地方式）**：数值证据由贝叶斯引擎处理——对每个描述保存信念的后验，序贯计算“当前环境与刚才同一环境”的后验（在线变点 / 潜在原因推断，regime 与 latent 学习器是其近似）；语言证据（线索句子）由 LLM 处理，其输出**不是指令**，而是一个带可靠度权重 *r* 的噪声传感器读数，作为一项似然因子并入后验（*r* 由它过去判断与后验的一致程度估计）。这样 LLM 读错只会降低而不会推翻后验。

**先决问题**：LLM 能否读懂线索句子？这是前面 G9 两次探针（Laya 的向量与问答特征）都没过的地方。若 LLM 也读不懂，语言证据不存在，融合就没有意义。

**探针 C（线索读取，开发期，非确认性；运行前写定）**：沿用 `packages/evo/cues.json`（3 个状态 × 6 训练句 + 6 评估句，评估句措辞与训练句不同、含词汇不重叠的说法；另有 6 条与状态无关的句子 noise）。对每个（训练句，评估句）与（训练句，无关句）配对，向 `deepseek-flash`（思考关闭）问“这两句是否描述同一类环境条件（温度、湿度、风、能见度），即使措辞很不同”，要求只回 JSON `{"same": 0..1}`；每对两种顺序各问一次取平均（共 864 次）。读数（与 G9 探针 2 同一套定义与门槛）：
1. 每个评估句取“与各状态训练句的平均相似概率”最大的状态，准确率 **≥ 0.9**；
2. train × eval 句对“同状态 vs 不同状态”的 AUC **≥ 0.9**；
3. 评估句到最近状态的相似度对无关句的 AUC **≥ 0.8**（无关句不应被当成已知环境）。
三项都过 = **LLM 能读线索**，进入 G11b（贝叶斯融合）的设计；有一项不过 = 不过，停止语言证据这一条。对照：词重叠（Jaccard）、打乱的相似概率。**不改阈值、不换句子再试。**

限制：句子由作者撰写；18 个评估句、一个模型、一版提示；评估句措辞可能偏易读；通过只说明“LLM 能判断两句是否同一类天气”，不说明它理解环境变化。

## 14. 探针 C 的结果（2026-10-28；`experiments/evo/g11-cue-probe-01/`，864 次调用、8 秒；模型 `deepseek-flash` 思考关闭）

| 读数（门槛） | LLM | 词重叠 Jaccard | 打乱的 LLM 概率 |
| --- | --- | --- | --- |
| 最近状态准确率（≥ 0.9） | **1.000**（18/18） | 0.500 | 0.444 |
| train × eval 句对 AUC（≥ 0.9） | **1.000** | 0.562 | 0.545 |
| eval 对无关句 AUC（≥ 0.8） | **1.000** | 0.824 | 0.644 |

**按运行前写定的判据：三项全过，LLM 能读线索**（无一句分错，无解析失败）。对照：G9 的两次探针里 Laya 向量（0.33 / 0.49）与 Laya 问答特征（0.83 / 0.89）都没过。

**下一步（G11b）**：语言证据存在，值得设计“贝叶斯引擎 + LLM 传感器”，在**线索措辞每阶段都改写**的世界里检验（同一状态每次出现换一句不同的话；按句子字面分表的 cue 学习器因此失效，regime 不读线索，只有会读语言的才有机会）。

## 15. G11b 实现与小探针（贝叶斯引擎 + LLM 传感器；2026-10-28）

**模拟器新增（默认关闭）**：线索模式 `paraphrase`——每个环境状态有一组不同措辞（`packages/evo/cues.json` 的训练句 + 评估句各 12 句），同一状态每次出现换一句（不与该状态此前用过的重复）。这使“按句子字面分表”的 cue 学习器失效，只有能读语言的才可能利用线索。`tests/ctx.test.mjs` 有测试。

**harness（`runBayesWorld`）**：
- 数值证据：每个个体维护“当前处于哪个环境表（或新环境）”的后验；每次经历按隐马尔可夫更新（换环境概率 h，高斯似然 σ，各表预测为均值，新环境预测很宽）；后验最大且 ≥ 0.6 且不是当前表时切换 / 新开。
- 语言证据：线索句子变化时，先把环境换了的先验提高（边界换环境概率 0.5），再让 LLM 判断“新句子与此前见过的每句是否同一类条件”（探针 C 的提示，两种顺序平均），经可靠度 r = 0.8 折算成各环境表的似然因子 f = r·s + (1−r)(1−s) 并入后验——**传感器读数，不是指令**。第一次见到线索时没有可比较的句子，不做任何事。
- 条件：**B** 只有数值贝叶斯；**BL** + LLM 传感器；**BLw** 传感器 30% 的查询被故意取反（检验读错的代价）；**BLo** 预言机传感器（用隐藏的真实状态，只作上限度量，不是个体可用的信息）。

**开发期超参数选择（披露）**：σ、h、决策阈值是数值引擎最敏感的参数（σ 小则乱切表，σ 大则几乎不切表）；用开发期种子 201、6 个世界、条件 B 与 BLo（无 LLM）在 6 组 (σ, h, 阈值) 上试过：(0.35, 0.02, 0.6) B 节省 +0.19 但 E0 仅 .55、适应度 .62（过度切表）；(0.5, 0.02, 0.6) +0.06 / .64 / .71；(0.7, 0.02, 0.6) −0.10 / .75 / .77，BLo +0.06 / .75 / .83；(0.5, 0.005, 0.6) −0.05；(0.7, 0.005, 0.8) −0.10，几乎不切表；(1.0, 0.005, 0.8) −0.15 = 完全不切表。**选定 σ=0.7、h=0.02、阈值 0.6**（B 本身不切坏世界、适应度不低于 plain，这样 BL 相对 B 的增益才主要来自传感器）。这是在 1 个种子上选的，没有在种子 202 上看过；**数值引擎未经进化训练，所以与 regime（基因组进化出的参数）不是对等比较**，R 仅作参照。

**探针设计（运行前写定）**：世界 A/B/A，K=6，线索 `paraphrase`，开发池 `test`，开发期基因组 plain 201、202，8 个个体，每个条件 8 个世界；条件 P、R、B、BL、BLw、BLo；模型 `deepseek-flash` 思考关闭。判据：
1. **语言证据有帮助**：BL − B 的节省 ≥ +0.10，且 BL 适应度 ≥ B 适应度，两个种子都满足；
2. **接近预言机**：BL 节省 ≥ BLo − 0.05；
3. **对读错稳健**：BLw − B 的节省 ≥ 0.5 × (BL − B)，且 BLw 的节省低于 BL；
4. 参照（描述，不入判据）：与 P、R 比较。
**不满足 1 = 无迹象，停止**；不改参数再试。

限制：数值引擎是手设参数；传感器对改写句的判断在探针 C 里近乎完美（偏容易）；每个条件 8 个世界、2 个种子；世界仍是模拟小世界；LLM 的“读懂线索”不等于“理解环境变化”。

## 16. G11b 小探针的结果（2026-10-28；`experiments/evo/g11b-probe-01/`，LLM 调用仅 48 次——同一世界里各个体的相同句对共用一次调用）

世界 A/B/A，K=6，线索 `paraphrase`（每次换一句），开发池 `test`，开发期基因组 plain 201 / 202，每个条件 8 个世界；σ=0.7、h=0.02、阈值 0.6、r=0.8。

| 条件 | 节省（201 / 202） | E2（回到 A 的早期占比） | 适应度 |
| --- | --- | --- | --- |
| P plain | −0.136 / −0.129 | .632 / .642 | .783 / .729 |
| R regime（参照，不读线索） | +0.095 / +0.206 | .757 / .852 | .864 / .863 |
| B 只有数值贝叶斯 | −0.130 / −0.065 | .618 / .691 | .736 / .720 |
| **BL 数值 + LLM 传感器** | **+0.053 / +0.028** | .800 / .785 | .813 / .752 |
| BLw 传感器 30% 取反 | −0.016 / −0.010 | .732 / .746 | .801 / .758 |
| BLo 预言机传感器（上限） | +0.064 / +0.038 | .811 / .794 | .812 / .764 |

**按运行前写定的判据**：
1. **语言证据有帮助：BL − B 的节省 ≥ +0.10，两个种子都要满足**——种子 201 为 **+0.182**，种子 202 为 **+0.093（差 0.007，未满足）**；BL 适应度 ≥ B 适应度两个种子都满足。→ **按规则判为“未达判据”，在本探针里停止，不改参数重试。**
2. 接近预言机：BL 节省 ≥ BLo − 0.05——满足（差 −0.011 / −0.009）。
3. 对读错稳健：BLw − B ≥ 0.5 × (BL − B) 且 BLw < BL——满足（+0.114 ≥ 0.091；+0.055 ≥ 0.047）。

**读法**：方向一致、幅度不小：数值引擎单独几乎不能保留（节省为负，接近 plain），加上 LLM 读线索后回到 A 的早期占比从 .62–.69 升到 .79–.80，适应度也升高；LLM 传感器几乎等于预言机；传感器 30% 读错时仍保留约一半以上的增益。但种子 202 差 0.007 没过线，且与 regime 相比仍落后（节省 +0.05 / +0.03 对 +0.10 / +0.21；适应度 .81 / .75 对 .86），而 regime 的参数是进化出来的，数值引擎是手设的，不是对等比较。这个探针只有 2 个种子、每个条件 8 个世界、一个世界。
**因此**：按写定规则，G11b 的开发期探针“未达判据”，不继续调参；但结果提示“LLM 读语言 + 数值贝叶斯”这条分工值得一次单独的、事先写好的确认性检验（新种子、新世界、冻结提示与参数），是否做由用户决定。

## 18. G12：四项扩展（用户 2026-10-29 要求继续推进：可靠度在线估计、LLM 做更多语言上的事、思考有代价、更难的世界）

**边界**：预注册 20、21 的训练与评估代码已冻结，不改；G12 的所有新东西放新文件（`structured-benv2.ts`、`build-cue-desc.ts`、`gen-llm-cues.ts`、`build-cue-matrix2.ts`），模拟器新选项默认关闭；本节全部是**开发期（非确认性）**，基因组是手设参数（开发期 plain 种子 201、202 的前 9 个基因 + σ 0.7、h 0.02、ν 0.3、rel0 0.8、hb 0.5），没有经过进化。

**1. 传感器可靠度由个体在线估计**：每次线索边界后记下传感器指向的环境（claim），经过 8 次经历后看后验：> 0.8 记一次正确，< 0.2 记一次错误，其间不记；rel = (a + 6·rel0)/(a + b + 6)，限制在 [0.5, 0.99]。对照 `gene`（固定 rel0）。
**2. LLM 做更多语言上的事**：（a）LLM 按状态属性**自己写**一批线索句（`cues-llm.json`，12 句 / 状态，与作者句无重合；只给属性，不给作者的句子），作为独立来源的措辞库（`cueBank: 'llm'`）；（b）LLM 对每句做**结构化命名**（温度 / 湿度 / 风 / 能见度 / 光线，句子没说的记 unknown，再给 2–3 词的环境名），由命名得到相容度矩阵（`cue-sim3.json`）——只提到部分属性的句子与若干环境相容，而不是勉强判“同一类 / 不同类”。传感器矩阵：`pair`（句对判断，`cue-sim2.json`）与 `desc`（命名相容度）。LLM 写“笔记再被后验引用”这类每个体在线调用的角色没有做：它与缓存、同步、可回放的设计冲突，列为后续。
**3. 思考有代价**：线索变化时发起传感器查询，证据在 L 个 tick 之后才到；`rest` 变体里这段时间个体休眠（照常耗能）。L ∈ {10, 40}，delay / rest。
**4. 更难的世界**：`cueFlaw`（默认关闭）：missing = 某个阶段整段无线索的概率，wrong = 某个阶段显示另一状态句子的概率（按 runId 与阶段哈希确定）；措辞库 llm；线索标签改为“出现后 8 次经历”落定。

**矩阵事实**（运行前已知，不是个体表现）：LLM 句库的句子很多只提到部分属性（72 句平均 2.15 个已知属性，17 句至多 1 个已知属性）。`cue-sim2.json`：全部 72 句里同状态句对均值 0.791（最小 0.05），不同状态句对均值 0.057（最大 0.85）——比作者 36 句（0.943 / 0.044，最小 0.60 / 最大 0.25）混乱得多，说明句对相似度判断在部分属性句子上不稳；`cue-sim3.json`（命名相容度）同状态均值 0.703（最小 0.5）、不同状态 0.419（最大 0.667）；命名的属性与作者写下的状态标签 0/146 矛盾（LLM 没有说错的属性，只是常常不说）。

**开发期判据（运行前写定；world = A/B/A/B/A，K=6，开发池 test，开发基因组 201 / 202，每格 5 个世界；节省 = 第 5 段早期 − 第 1 段早期）**：
- **R（在线可靠度）**：在“误导 0.3”与“缺失 0.3 + 误导 0.3”两个世界里，online 的适应度 ≥ gene + 0.02（两个种子）；在干净世界里 online ≥ gene − 0.02。
- **L（语言角色）**：LLM 句库干净世界里，`pair` 与 `desc` 各自对 plain 的节省差 ≥ +0.10 且适应度 ≥ plain + 0.03；`desc` 与 `pair` 谁更好只作描述。
- **T（思考代价）**：online 版本的 L=10 / 40、delay / rest 变体，保留“相对 plain 的适应度增益”的比例（增益 = 变体适应度 − plain 适应度）≥ 0.5 记为“耐受”。
- 以上全部是描述性读数，不触发“停止”规则；读数后写下什么值得进入预注册，什么不值得。
