# 设计 G11：双系统架构——Laya（系统 1）+ LLM（系统 2）+ harness（记忆与观测）

状态：**已开工**（2026-10-28 用户确认：DeepSeek，模型名用 `deepseek-flash`，即官方文档当前推荐的 Flash 名，由 DeepSeek-V4.1-Flash-1017 提供服务；旧名 `deepseek-v4-flash` 已被官方改指向同一模型；key 由用户放进本地 `.env`；费用不设预算上限，代码里只保留防失控的调用数保护 `LLM_MAX_CALLS`，默认 200000）。S1（harness、桩模型、条件 T、记录回放、测试 7 项）已完成；探针脚本 `packages/evo/dual-probe.ts` 已写好，等 key。用户 2026-10-28 决定：LLM 用用户提供的 API key；目标是验证新的架构假设（双系统），可以做的研究因此更多。旧链路（结构化个体 + 进化先天 + 终身学习）保留为基线，预注册 20 照常完成。

## 1. 假设（架构层面）

旧链路里最弱的环节都是“需要推理”的：环境变了靠预测误差启发式发现（regime）；线索只能当标签（cue）；固定 Laya 读不出线索含义（G9 两次探针未过）。**假设 A**：让一个会推理的系统 2 在“意外”时介入，读自己的经历（和可见的线索句子），判断“环境是否变了、是不是见过的环境”，由 harness 去切换 / 新开信念表，可以在 A/B/A 世界里取得接近或超过 regime 的保留，并且在 regime 做不到的地方（读线索、解释变化）有额外收益。**可证伪**：若系统 2 的保留不优于“同样触发条件 + 规则化动作”的对照，则增益不来自推理。

## 2. 架构（谁拥有什么）

```
世界（模拟器：唯一的状态所有者）
  └─ 每个 tick：个体的局部观测（含可选的线索句子 season）
系统 1（每 tick，快）：结构化个体 = 固定 Laya 先验 + 个体信念表（预注册 17 的 plain 基因组，冻结，不再进化）
harness（个体私有）：
  ├─ 经历日志：最近 N 次“吃了什么描述 → 结果（以文字档位表述）”
  ├─ 记忆笔记：系统 2 写下的短句（上限 M 条，只含该个体自己的经历）
  ├─ 意外触发器：预测误差滑动平均超过阈值，带冷却
  └─ 动作执行器：把系统 2 的结构化建议变成对系统 1 的操作（新开表 / 切到第 i 张表 / 保持）
系统 2（只在触发时，慢）：LLM，输入 = 经历日志 + 笔记 + 当前表摘要 + （可选）线索句子；输出 = 严格 JSON（是否变了、假设一句话、建议、要写的笔记）
```

不变量：LLM 只提交“信念管理”的建议，不能改能量、位置或存活；个体输入只含自身状态、有限记忆与局部观测，**隐藏真值（食物真实影响、环境状态）不进入提示**；提示里的结果用个体自己感受到的档位（“恢复了能量 / 损失了能量”），不给环境阶段名；先天（基因组）/ 后天（信念表、笔记）/ Laya 感知 / **系统 2 推理**四个来源分别标注；Laya 权重不变，LLM 权重不变；每次调用的输入、输出、模型版本、耗时、费用记录在案，迟到或失败的响应按“无建议”处理，不阻塞世界。

## 3. 世界时间与系统 2 的耗时

第一版：**系统 2 的思考不占模拟时间**（世界在等待时暂停）——这是一个明确披露的简化，等价于“推理瞬间完成”。它高估了系统 2 的价值。后续变体：每次调用扣固定的模拟 tick 或能量（“思考有代价”），再比较。

## 4. 对照条件（探针与预注册共用）

| 条件 | 内容 |
| --- | --- |
| P | plain：系统 1 单独（预注册 17 基因组） |
| R | regime：启发式分表（基线，已有） |
| T | **触发 + 规则动作**：同样的意外触发器，动作用启发式（意外 → 新开一张表 / 切到误差最小的表），无 LLM（隔离“触发”本身的作用） |
| S2 | 触发 + LLM（无线索） |
| S2c | 触发 + LLM + 真实线索句子可见 |
| S2x | 负控制：LLM 收到被打乱 / 空白的经历日志（检查它是不是真在读经历） |

## 5. 小探针（开发期，非确认性）

世界：K=6，A/B/A，无线索（再加线索版），开发方言池 `test`，开发期基因组（种子 201、202 的 plain），个体 8 个，立即反馈；每个条件 8 个世界。指标：节省（同预注册 18）、适应度、LLM 调用数与 token 数。先写的读法：
- **系统 2 有迹象**：S2 的节省 − T 的节省 ≥ +0.05 且 S2 ≥ R − 0.05（两个种子方向一致）→ 值得设计预注册；
- **无迹象**：S2 ≤ T + 0.02 → 增益不来自推理，停；
- 其他 → 不确定；S2x 若接近 S2，说明 LLM 没在读经历，停。
探针规模：约 8 个个体 × 每个体一生若干次调用（每个反转前后各触发数次，上限 12 次 / 一生）；实际调用数将在开跑前用桩模型测出，并按所选模型的价格给出具体费用估算，**设硬上限**（达到即停）。

## 7. 需要你确认的三件事

1. **API 与模型**：用哪家的 API、哪个模型？（我建议探针先用较小、较便宜的模型，确认有迹象后再换大模型重复一次。）
2. **key 的交付方式**：请不要把 key 贴在对话里。我会读环境变量（默认 `LLM_API_KEY`，以及 `LLM_BASE_URL` / `LLM_MODEL`），代码里不落盘、不进日志、不进仓库（`.env` 已加入 `.gitignore`）。你在终端里 `export` 即可，或写进本地 `.env`，我读取不回显。
3. **费用上限**：探针的总费用硬上限是多少？到达即停，并在文档里记录实际花费。正式评估前我会再给一次估算让你确认。

## 8. 风险与限制

- 世界时间不计思考成本（见 §3），第一版会偏乐观；LLM 输出有随机性与版本漂移，所以所有调用记录在案，评估靠记录回放而不是随机种子；
- 提示措辞是自由度很大的设计选择，探针只试一版，不据结果反复调提示再重跑（调提示须在开发期、记录并披露）；
- 若系统 2 只是在“检测到意外就新开一张表”，那它与 T 无差别——这正是条件 T 存在的原因；
- 线索句子由作者撰写，LLM 读得懂不代表理解了环境；它回答的是“能否用语言读线索”，不是“Laya 是否理解环境”。

## 9. 冒烟记录（2026-10-28，接入 DeepSeek 的第一次调用）

- 1 个世界、S2，思考模式缺省开启、max_tokens 400：55 次调用里 **17 次返回空内容**（推理 token 用完上限），19 次解析失败，仅 1 次动作被采纳。原因是官方缺省 `thinking: enabled`，推理 token 占用 max_tokens。
- 同一批 6 条提示（4 条“结果与表的预期不一致”）对比：**思考关闭**（max_tokens 300）1.5 秒、193 个输出 token，4 条不一致里 3 条判 new、1 条 keep；**思考开启**（max_tokens 4000）22.4 秒、6650 个输出 token，3 条判 new、1 条 keep。判断质量相近，思考关闭快约 15 倍、输出 token 少约 34 倍。
- **决定**：探针主条件用思考关闭（`LLM_THINKING=disabled`，缺省）；若有迹象，再加一个思考开启的变体重复。冒烟日志不进入探针（探针另开输出目录，缓存键含提示，不会混用）。
- 观察：意外触发器在稳定阶段也常触发（约每个体 7 次 / 世界），系统 2 大多回答 keep，对误报不敏感；条件 T 同样触发 68 次 / 世界。这是触发阈值 0.5 偏敏感，不改（探针不据结果调阈值）。

## 10. 小探针 v1 的结果（2026-10-28；`experiments/evo/g11-probe-01/`，调用日志 `llm-log.jsonl`，2916 次调用、约 205 万输入 / 10.5 万输出 token、平均 0.82 秒 / 次；开发期基因组 plain 201、202；A/B/A、K=6、开发池 test；每个条件 8 个世界；模型 `deepseek-flash` 思考关闭）

| 条件 | 节省（种子 201 / 202） | 适应度（201 / 202） | 每世界调用数 |
| --- | --- | --- | --- |
| P plain | −0.136 / −0.129 | .783 / .729 | — |
| R regime（基线） | +0.095 / +0.206 | .864 / .863 | — |
| T 触发 + 规则动作 | −0.050 / −0.049 | .639 / .694 | 66 / 70 次触发 |
| **S2 触发 + LLM** | **−0.157 / −0.171** | .752 / .737 | 72 / 72 |
| S2c + 可见线索 | −0.169 / −0.126 | .754 / .722 | 76 / 75 |
| S2x 负控制（结果错配） | −0.233 / −0.165 | .643 / .641 | 68 / 67 |

**按运行前写定的判据读数**：S2 − T = −0.107 / −0.123（判据要求 ≥ +0.05），S2 ≤ T + 0.02 → **无迹象**；S2 也不接近 R（落后约 0.25–0.38）。S2 的节省与不用系统 2 的 P 几乎相同。负控制 S2x 的适应度明显低于 S2（.64 对 .74–.75），说明 LLM 确实在读经历（错配会伤害它），但读了之后没有比 plain 做得更好。S2c 与 S2 无差别：可见线索没有带来可见的收益。

**决策分布**（所有调用）：S2 keep 719 / new 182 / switch 102；S2c 759 / 154 / 139；S2x 414 / 337 / 110。在提示里明确出现“结果与当前表预期相反”的 460 条 S2 调用里，LLM 仍有 219 条（48%）回答 keep。调用发生时已有 1 / 2 / 3 / 4 张表的比例为 560 / 238 / 117 / 88。

**诊断（harness 设计层面的疑点，未检验）**：触发器用绝对阈值 0.5，稳定阶段也每个体约触发 9 次 / 世界（上限 12 次 / 一生），可能在反转与回归发生前就把调用与冷却用掉，并让表空间被误报占满；T 也有同样问题，且 T 的适应度比 P 还低。所以 v1 的“无迹象”既可能是系统 2 本身无用，也可能是触发器太差。按设计 §8 的约束，v1 的结果照实记录，不改判据；允许在开发期做**一次披露的第二轮**，只改触发器（见 §11），提示与判据不变。

## 11. 第二轮（v2，开发期，运行前写定）

**只改触发器，提示、判据、世界、基因组、模型设置不变**：触发条件改为“当前表的误差滑动平均 > 0.35，且比该个体自己的慢基线（误差滑动平均的慢速平均，速率 0.02）高出 0.2”，即只在误差**上升**时触发；每个体一生的调用上限 12 → 20；冷却 100 tick 不变。T 使用同一触发器。判据同 §5：**有迹象** = S2 − T ≥ +0.05 且 S2 ≥ R − 0.05，两个种子方向一致；**无迹象** = S2 ≤ T + 0.02；S2x 接近 S2 说明 LLM 没在读经历。**不再有第三轮**：v2 的结果无论如何照实记录；若有迹象，才设计预注册 22（新种子、新世界、新提示冻结）；若无迹象，G11 的结论是“在这一版 harness 与提示下，系统 2 没有带来保留收益”。

## 12. 小探针 v2 的结果（2026-10-28；`experiments/evo/g11-probe-02/`，1216 次调用；触发器改为“误差上升”，其余同 v1）

| 条件 | 节省（种子 201 / 202） | 适应度（201 / 202） | 每世界触发数 |
| --- | --- | --- | --- |
| P plain | −0.136 / −0.129 | .783 / .729 | — |
| R regime | +0.095 / +0.206 | .864 / .863 | — |
| T 触发 + 规则动作 | −0.092 / +0.030 | .671 / .664 | 35 |
| S2 触发 + LLM | **−0.139 / −0.171** | .752 / .733 | 31 |
| S2c + 可见线索 | −0.122 / −0.140 | .810 / .762 | 32 / 31 |
| S2x 负控制 | −0.190 / −0.041 | .651 / .714 | 31 / 32 |

**按 §5 / §11 的判据**：S2 − T = −0.047 / −0.200（要求 ≥ +0.05）；S2 ≤ T + 0.02 → **无迹象**。触发数从约 70 降到约 31 / 世界，但节省没有改善。S2c 的适应度比 S2 高约 0.03–0.06（.810 / .762 对 .752 / .733），节省差别仍在噪声内；这是“可见线索略有帮助”的一个弱提示，未检验。S2x 在种子 202 上的节省（−0.04）反而好于 S2，说明这一轮的节省指标噪声很大（每个条件仅 8 个世界）。

**结论（v1 + v2，按 §11“不再有第三轮”）**：在这一版 harness 与提示下，LLM 系统 2 **没有**带来保留收益；它的节省与不用系统 2 的 plain 接近，明显低于 regime。可能原因（均未检验）：LLM 对带噪声的少量样本不敏感（对“结果与预期相反”的提示仍常回答保持）；单次结果噪声大，序贯概率推理不是 LLM 擅长的；新开的表是空表，切换后要重新学习。这与用户提出的“LLM 读到不准确的经历会被误导，应引入贝叶斯式的概率推理辅助”的判断一致，下一步设计见 §13。
