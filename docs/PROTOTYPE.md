# 产品原型计划

状态：2026-09-29 已按用户指示完成 P0.1–P0.3 首版产物及浏览器自查；P0.4 已收到文字简化、至少三种角色共存和算法优先的反馈；完整流程验收仍待完成。

实际产物与视觉约定见 [P0 设计与交付](p0/DESIGN.md)，操作证据见 [走查记录](p0/VERIFICATION.md)。下文保留完整目标规格，未实现部分以交付记录为准。

## 1. 原型要回答的问题

用户进入应用后，能否理解世界正在发生什么，找到值得跟随的生命，通过干预观察它如何改变，并分清“策略更新了”和“学得更好了”？

P0 验证信息组织、操作和视觉体验；M0 验证真实模型与最小学习闭环。两者都为完整开发提供依据，原型中的示例行为不能证明技术可行或真实涌现。

## 2. 首次使用的核心流程

```mermaid
flowchart LR
    START[选择预设并进入生态缸] --> WATCH[观察世界]
    WATCH --> SELECT[选中并跟随一个生命]
    SELECT --> HISTORY[查看经历与行动]
    HISTORY --> CHANGE[投放营养或改变资源场景]
    CHANGE --> ADAPT[查看行为与策略变化]
    ADAPT --> FORK[创建学习与冻结分支]
    FORK --> COMPARE[比较结果并返回世界]
```

首次进入推荐一个预设场景，默认收起技术参数。种子、奖励配置和训练预算放入实验设置，不要求用户先理解这些概念才能观察世界。

P0 使用短小的可重置演示脚本呈现这条流程。长期结果通过明确的演示时间跳转展示，不要求用户为了审核界面等待数代模拟，也不把跳转展示成真实训练。

## 3. 核心视图

以一个世界工作台为主，个体观察和成长展示采用侧栏或抽屉，不把所有信息拆成独立页面。

| 视图 | 主要内容 | 主要操作 | 产品阶段 |
| --- | --- | --- | --- |
| 开始与预设 | 场景简介、运行模式、已有存档 | 进入推荐世界、调整设置、恢复存档 | M2 起 |
| 世界工作台 | 生态画布、资源图层、时间、种群、运行状态 | 缩放、移动镜头、暂停、单步、跟随 | M2 |
| 生命观察侧栏 | 身体性状、能量、可见范围、地点记忆、当前动作 | 选中、固定跟随、查看经历 | M2–M3 |
| 成长抽屉 | 事件、Laya 偏好、最终选择、策略版本及前后比较 | 选事件、比较固定观测下的策略、暂停参数学习 | M5 |
| 环境干预 | 营养笔刷、障碍、资源场景设置 | 预览范围、应用或取消本次操作 | M2；变化资源实验 M5 |
| 实验对照 | 相同快照的学习/冻结分支、条件差异、结果曲线 | 创建分支、切换世界、查看完整结果 | 基础分支 M4；学习对照 M5 |

P0 会提前展示 M5 的体验，以便先验证产品方向；这种提前展示不代表功能提前实现。谱系先以观察侧栏的简化入口呈现，复杂谱系导航不阻塞核心原型。

## 4. 信息层级与视觉稿

桌面主画面采用中央生态画布、顶部紧凑控制栏、右侧可收起观察面板和底部按需展开的时间线。默认优先展示生命和环境，选中个体后再显示感知范围、目标和记忆标记。

视觉基调沿用深色显微生态：深蓝绿水域、半透明有机轮廓、温和光晕、低对比背景与清晰文字。颜色和形态映射数据含义，避免装饰动画遮住动作和状态。完整配色、字号、间距、图标与动效约定在视觉稿中落实。

拟检查桌面 1440×900、紧凑窗口 1024×768 和窄屏 390×844；这些是原型审核尺寸，不是已完成的设备支持承诺。窄屏首版采用纵向生命档案与可滚动弹层，不强求同时展示所有图表；原拟底部抽屉保留为用户走查后的改进候选，减少初版叠层操作。

用户已确认三种基础体型共存。P0 保持一套视觉语言，默认以世界和干预为主，技术细节按需展开。之后的视觉打磨优先支持真实行为辨识，不延后算法验证，也不增加预设的成长成功剧情。若出现具体分歧，再做局部替代方案，不一开始铺开多个完整主题。

## 5. 必须画出的状态

| 状态 | 用户必须能理解什么 |
| --- | --- |
| 未选择生命 | 可以点选什么，如何开始观察 |
| 无经历或尚未更新 | 此个体尚无数据，不用伪造曲线填充 |
| 等待推理或训练 | 世界在等待，界面可操作，模拟时间没有继续流逝 |
| 世界暂停 | 行动与学习提交都暂停；恢复与单步明确 |
| 参数学习暂停/冻结评估 | 世界仍可运行，参数不更新；记忆规则另有说明 |
| 请求失败或降级 | 发生了什么、实际使用哪个大脑、如何重试或切换 |
| 选中个体死亡 | 停止跟随，保留个体经历，支持返回世界或查看后代 |
| 种群灭绝 | 显示完整结果与重开/恢复入口，不伪装成加载中 |
| 学习没有改善 | 如实展示无差异或退化，不只设计成功故事 |
| 保存或恢复受限 | 区分可以观看的回放与可以继续训练的完整快照 |

首次干预明确区分“关闭面板”和“取消尚未应用的操作”。已应用的营养或障碍修改不承诺一键撤销整个因果后果；需要恢复时使用之前的快照。

## 6. 原型数据与真实能力

可点击原型可以采用本地固定示例和脚本化动画，但应始终显示“交互原型 · 示例数据 · 未连接模型”。按钮展示加载、结果或失败等设计状态，不能暗示完成了实际推理、训练或文件保存。

示例数据单独存放，标明生成方式和所演示的场景，不混入 experiments 的真实评估结果。原型演示至少包含一个没有改善或失败的分支。截图和导出展示也保留原型标识。

世界、个体、经历、动作偏好、学习版本与实验条件使用与领域协议一致的命名，为 M2/M5 接入留接口。视觉组件可以复用，但应先验证数据契约，不为保留原型而让正式模拟器迁就演示脚本。

## 7. P0 交付顺序

| 子步骤 | 交付物 | 完成条件 |
| --- | --- | --- |
| P0.1 信息架构与线框 | 核心流程、视图布局、状态线框 | 覆盖第 2–5 节，可走通主流程和失败路径 |
| P0.2 视觉定稿候选 | 世界工作台、个体观察、成长抽屉高保真稿及基础样式约定 | 能评价生态质感、可读性和窄屏布局 |
| P0.3 可点击原型 | 本地可操作原型、固定示例、简短操作说明 | 主要控件有可理解反馈，流程可重置，无伪装的真实模型能力 |
| P0.4 用户走查与修订 | 操作反馈、问题清单、修订后的原型 | 用户能按下列脚本完成操作，阻碍核心理解的问题已修复 |

默认在可点击原型形成后进行一次集中用户走查；线框与视觉阶段可随工作展示进度，不设置每一步都必须再次批准的流程。

## 8. 走查脚本与验收

1. 从预设进入世界，找到一个生命并跟随，能说明它现在在做什么。
2. 查看一段经历，指出 Laya 偏好、最终选择和实际后果的区别。
3. 投放营养或选择变化资源场景，能判断操作是否已生效。
4. 分别暂停世界和暂停参数学习，能理解二者区别。
5. 查看学习前后对比，能区分“策略变化”和“有评估证据的改善”。
6. 创建演示中的学习/冻结对照，能看到两边的条件差异和数据性质。
7. 遇到失败、死亡或没有改善时，知道接下来能做什么。

由实际操作和用户反馈记录结果，不凭截图宣称流程通过。P0 完成意味着核心体验可评审、可理解；它不验证模拟性能、模型能力或真实学习效果。

## 9. 当前准备度

产品愿景、主路线、机制顺序与实验方向已明确。实际线框、视觉候选与可点击原型已产出；待完成用户走查与修订，以及真实模型和小策略预研。原型自查不替代用户反馈。

完整开发前至少需要：P0 核心流程无阻碍性问题，M0 有真实调用与最小学习闭环证据，并据此确定首版预算与接口。当前不以补齐文档代替完成上述验证。
