## 优化原则

1. **先量，后改。** 每项性能改动附基线与改动后数字、机器和命令。没有数字不声称更快。
2. **行为不变是硬约束。** 重构前后，同一种子/同一记录的世界终态哈希、严格回放结果必须一致。需要改变行为的改动不属于本轮，另行讨论并更新文档。
3. **不改模型数值而不说明。** 固定 Laya 的推理优化须对比概率输出；不一致必须标注为新版本，不得静默替换。
4. **不碰历史证据。** `experiments/*/evidence` 与 `docs/m0/` 只读保留；不重写、不重命名、不补造。
5. **小步切片。** 每片有输入、产物、验证；通过 `scripts/verify.sh` 才算完成。
6. **先删复杂度再加机制。** 能删除重复代码就不新增抽象；不引入大框架、云服务或额外模型。
7. **边界不退让。** 模拟器拥有世界；模型只提议动作；训练输入不泄露隐藏状态；决策与更新去重并绑定版本。优化不得削弱这些约束（见 AGENTS.md）。
8. **测试彼此独立。** 无模型的测试不依赖网络或下载；模型能力测试与逻辑测试分开。
9. **不自动提交、推送、发布。** 提交由用户指示。

## G5 Laya 推理测量（2026-10-02，M4 / MPS / fp16 autocast，laya 0.3.21）

方法：`services/ecology/profile_laya.py` 重放 `real-smoke-01` 记录的 64 条真实请求（8 轮 × 8 个体），结果 `experiments/perf/laya-baseline-2026-10-02.json`。

| 发现 | 数据 |
| --- | --- |
| 数值基线可逐位复现 | 与原记录相比最大概率差 0.0，64 个动作全部相同。该脚本可作为任何推理改动前后的数值对照 |
| 一轮（8 个体）总耗时 | 约 2.7–3.3 秒，早先估计的 10 秒/轮含当时的其他开销，不能用作当前推理成本 |
| 分词与编码 | 合计约 15 ms/轮，不是瓶颈 |
| 耗时主体 | 前向计算（`.cpu()` 同步等待），约 0.35–0.4 秒/个体；模型 4.2 亿参数，单次序列约 700 token |
| 按候选集分组 | 不同个体候选集不同，一轮被拆成约 4 次前向。合并成一次混合前向实验：**更慢**（4.2 秒 vs 3.4 秒），概率最大偏差 0.0127，故不采用 |
| 权重整体转 fp16 | 在 MPS 上触发 `MPSNDArrayMatrixMultiplication` 底层失败，不可行 |

结论：在固定模型、固定输入模板下，推理是算力受限，没有不改数值的大幅提速。有意义的杠杆只剩缩短提示词（状态约 380 token，问题与选项约 70 token）或减少个体数/决策频率，这会改变模型输入，属于算法层面，留待算法讨论，不在本轮擅自改。

已修复：`laya_provider.py` 每次加载会在 `.models/runtime/` 留下一个临时目录且从不清理（已累积 22 个，均为硬链接副本，原权重未受影响）。现在目录名带进程号，进程退出时清理，并在下次启动时回收创建者已不存在的目录（SIGTERM 下 atexit 不一定运行，端到端验证中发现），旧目录已删除，`.models` 从 1.5 GB 降到 1.4 GB（占用主要是单份权重）。

注意：该脚本和探索使用了私有接口的结论仅限本版本库（0.3.21）；升级库后须重新对照基线。

## 工程约定（随改动沉淀）

- 验证入口只有 `scripts/verify.sh`；Python 测试逐文件运行，因为 `services/m0` 与 `services/ecology` 有同名模块。
- 修改 `ecology.ts` 或 `protocol/ecology.ts` 后，若契约测试失败：先判断是否有意改变；有意则运行 `node scripts/gen_contract_fixture.mjs`，确认 Python 契约测试通过，并在此记录。无意则修代码。
- 修改模拟行为会使 `tests/golden.test.mjs` 失败；这等于改变了实验可比性，必须升级 `ECOLOGY_VERSION` 并记入此文档，不得只改哈希。
- 服务状态只通过 `ServiceState`；新增端点自动获得访问日志与指标，无需手写。
- 服务启动参数：`--without-laya` 只用于无模型的独立 PPO 与测试；`--port` 默认 8767，与 Vite 代理一致。
- 前端验证入口：`scripts/verify.sh --ui`（或 `npm run test:ui`）。冒烟脚本自行启动 Vite，使用规则模式，不依赖模型服务；新增交互功能时同步补一步。
- 拆分前端文件时按“原样搬运 + 类型检查 + 冒烟”进行，不在同一次改动里改行为。
- 2026-10-02 端到端验证：重构后启动带真实 Laya 的服务，`/decide` 对 `real-smoke-01` 第 2 轮 8 条请求返回的概率与原记录逐位一致，MPS，无 CPU 降级。

## 精简模式（2026-10-21）：进化 / 评估的模拟速度

**性能分析**（`node --cpu-prof`，4 个池世界、延迟 40、结构化个体）：`stateHash` 占 43%，`structuredClone` + `clone` 约 21%，两者合计约 64%；而进化与评估只读取 `accepted / outcomes / events`。

**做法**：`Ecology.lean`（默认 `false`）。精简模式下：不计算整状态哈希（`snapshotId` 改为 `lean:<epoch>:<tick>`，每轮唯一，过期提案仍被拒绝）；`requests()` 直接返回内部数组（调用方不得修改）；`step()` 只返回 `accepted / outcomes / events`。`runSemanticWorld` 默认使用精简模式，`LFE_LEAN=0` 回到完整模式。

**结果**：同一批世界，每个世界 1869 ms → 333 ms（约 5.6 倍），适应度逐位相同（`fitness sum 1.755082` 两种模式一致）。

**保证**：`tests/lean.test.mjs` 对普通池世界、延迟、漂移、成熟周期、社会观察五种配置、blind / oracle / structured 三类控制器，比较 `runSemanticWorld` 的完整返回值（深度相等）；并逐轮比较两种模式下的 outcomes 与 events；黄金测试与全部原有测试通过。完整模式的行为未改变，因此已冻结的预注册评估代码仍可逐位复现。

**已知问题（与精简模式无关）**：drift + 预言机 + 种子 12 在原始代码里就会抛出 `invalid_agent`（两种模式都会）。尚未查明原因；此前的漂移实验没有使用该种子。
